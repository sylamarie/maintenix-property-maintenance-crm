# Deploying Maintenix online

This guide puts the Maintenix **API** and **database** online and connects them to the website on Vercel. Everything uses free plans and no credit card.

| Piece | Where it runs | What it does |
|---|---|---|
| Website (React) | Vercel | The pages people see |
| API (Express) | Render | Checks logins, reads and writes data |
| Database (PostgreSQL) | Neon | Stores the data |

The website talks to the API, and the API talks to the database. Each piece needs the address of the next one, which is what most of the steps below are about.

> **Keep secrets private.** The Neon connection string contains your database password. Never paste it into chat, GitHub, a screenshot or a file in this repository. Only type it into the Render dashboard and into your own terminal window (step 2).

## Before you start

1. The code with `render.yaml` must be on the **`main`** branch of your GitHub repository (merge the pull requests first). Render reads that file from `main`.
2. Accounts (all can sign in with your GitHub account): [Neon](https://neon.tech), [Render](https://render.com). Vercel you already have.
3. Find your website's live address in Vercel (Project > Domains, for example `https://maintenix-something.vercel.app`). You need the exact production address.

Button names on these websites change from time to time. If a button is called something slightly different, look for the closest match.

## Step 1 - Create the database (Neon)

**What to do**

1. In Neon, create a new project. Name it `maintenix`, pick the region **Singapore** (closest to you; use the same region for Render), keep the default Postgres version.
2. On the project page, open **Connection Details** (or **Connect**).
3. Copy the **connection string**. It looks like `postgresql://user:password@ep-something.neon.tech/neondb?sslmode=require`. Keep it somewhere private for the next two steps.

**Why:** this string is the address and password of your database. `sslmode=require` makes the connection encrypted, which hosted databases demand.

## Step 2 - Create the tables and demo data (from your computer)

**What to do** - open PowerShell and run these lines one at a time. Replace the two quoted values.

```powershell
cd C:\Users\syla\maintenix-property-maintenance-crm
$env:DATABASE_URL = "paste-the-neon-connection-string-here"
$env:DEMO_PASSWORD = "choose-a-password-of-12-or-more-characters"
npm run db:schema
npm run db:seed
Remove-Item Env:DATABASE_URL, Env:DEMO_PASSWORD
```

**What each line does**

- `$env:DATABASE_URL = ...` tells the next commands to use the Neon database instead of your local one. It lasts only for this PowerShell window and is not saved to any file.
- `$env:DEMO_PASSWORD = ...` is the password the three demo accounts will get. This is the password you give to employers. The seed script refuses to run on a hosted database without it, so the public `Password123` can never end up online.
- `npm run db:schema` creates the tables.
- `npm run db:seed` adds the three demo accounts and sample clients, properties and jobs.
- `Remove-Item ...` forgets both values.

**Expected result:** `Database schema applied successfully.` and then `Demo users, clients, properties, jobs, job notes, and variations seeded successfully.`

**Demo accounts** (password = the `DEMO_PASSWORD` you chose): `admin@maintenix.com`, `operative@maintenix.com`, `client@maintenix.com`.

## Step 3 - Create the API (Render)

**What to do**

1. In Render, click **New +** and choose **Blueprint**.
2. Connect your GitHub account and pick the `maintenix-property-maintenance-crm` repository (branch `main`).
3. Render reads `render.yaml` and shows a service called `maintenix-api`. It asks for two values:
   - `DATABASE_URL`: paste the Neon connection string from step 1.
   - `CLIENT_URL`: paste your Vercel website address, exactly, starting with `https://` and **without a slash at the end**.
4. Click **Apply** / **Deploy**. The first build takes a few minutes.

**Why:** Render builds and runs the API. `CLIENT_URL` is the only website allowed to call your API (a safety rule called CORS). `JWT_SECRET` (the key that signs logins) is generated by Render automatically, and you never need to see it.

**Check it worked:** when Render says the service is live, open `https://YOUR-SERVICE-NAME.onrender.com/api/health` in your browser (the exact address is shown at the top of the service page). You should see `"status":"ok"` and `"database":{"status":"connected"`. If you see `"degraded"`, the database address is wrong (see Troubleshooting).

## Step 4 - Connect the website to the API (Vercel)

**What to do**

1. In Vercel open your project, then **Settings > Environment Variables**.
2. Add a variable named `VITE_API_URL`. The value is your Render address plus `/api`, for example `https://maintenix-api.onrender.com/api`. Tick **Production**.
3. Go to **Deployments**, open the latest production deployment's menu and choose **Redeploy**.

**Why:** the website is built once and has the API address written into it at build time. Changing the variable does nothing until it is rebuilt, which is what Redeploy does.

If your Vercel project builds from the repository root instead of the `client` folder, set **Settings > General > Root Directory** to `client`. The file `client/vercel.json` makes links such as `/admin/jobs` work when you reload the page.

## Step 5 - Try it

Open your Vercel website, sign in as `admin@maintenix.com` with your `DEMO_PASSWORD`, and click through the jobs page.

## One-click demo sign-in (optional)

The login page has three buttons (Admin, Operative, Client). When **demo sign-in** is on, clicking a button signs the visitor straight in, with no password. This is how employers can look around without asking you for a password.

**To switch it on:** in Render open **maintenix-api > Environment**, add a variable named `DEMO_LOGIN_ENABLED` with the value `true`, and save. Render restarts the API. (Services created from `render.yaml` get it automatically.)

**To switch it off:** change the value to `false` (or delete the variable). The buttons then fill in the email only and visitors must type a password.

**What it means:** anyone who opens your site can click a role and use the app as that role, including the admin, and can change or delete the demo data. Only the three demo accounts can be used this way. Real accounts always need a password, and the feature is off unless you turn it on.

**To reset the demo data** after someone has changed it, run `npm run db:seed` again with `DATABASE_URL` and `DEMO_PASSWORD` set (step 2). It restores the sample records and the demo accounts.

**Changing the demo password:** run `npm run db:demo-password` in the project folder. It asks for the connection string and the new password (12+ characters) on screen, shows a `*` for each character instead of the text, and changes only the three demo accounts' passwords. Nothing else is touched and nothing is saved to a file. With demo sign-in on, the password only matters if you sign in by typing it.

## Things to know about the free plans

- **The API sleeps.** After about 15 minutes with no visitors, Render stops the API. The next visit waits about 50 seconds while it wakes up. It is normal. Open the site before showing it to someone.
- **Photos do not last.** Uploaded photos are saved on Render's disk, which is wiped on every redeploy and restart. For a portfolio demo that is acceptable (the demo data has no photos). To keep photos, the next step would be cloud storage such as Cloudinary or S3.
- **Neon pauses an idle database** and wakes it automatically on the next request, adding a short delay.
- **Preview links will not log in.** Vercel creates a different address for every branch. Only the address you put in `CLIENT_URL` is allowed to call the API.

## Troubleshooting

| What you see | Likely cause | Fix |
|---|---|---|
| Browser console shows a CORS error, or login says `Origin not allowed` | `CLIENT_URL` on Render does not exactly match the website address | Fix it in Render (Environment). Include `https://`, no slash at the end. Render restarts the API |
| Login says "Network Error" | `VITE_API_URL` is missing or wrong, or you did not redeploy | Check step 4 and redeploy |
| `/api/health` shows `degraded` | `DATABASE_URL` is wrong or the Neon database was deleted | Copy the connection string again in Neon and update it in Render |
| `Too many failed login attempts` | 5 wrong passwords in 15 minutes from your network | Wait 15 minutes |
| Render deploy fails with `JWT_SECRET must be set...` | The generated secret was removed from the environment variables | In Render add `JWT_SECRET` and press "Generate" (or paste a 32+ character random value) |
| Everything is slow the first time | The free API was asleep | Wait about a minute, then try again |
